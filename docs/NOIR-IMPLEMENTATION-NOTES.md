# Obsidian Celluloid v0.3.0 — implementation notes

This release adds **Obsidian Celluloid Noir** (`vs-dark`, JSON type `dark`)
alongside the exact approved **Obsidian Celluloid (Light)** (`vs`, type `light`).
Extension identity, minimum engine, Light contribution and file icon identifier
remain unchanged. Both themes ship in one official `@vscode/vsce` package, with
no activation code, runtime dependencies, webviews or automatic settings changes.

## Generation architecture and changed files

| File(s) | Role/change |
| --- | --- |
| `design/noir-tokens.json` | Independent dark palette; original `design/tokens.json` untouched |
| `scripts/lib/theme.mjs` | Shared workbench groups and TextMate/semantic categories extracted from the original generator without changing Light output |
| `scripts/lib/noir.mjs` | Explicit Noir surfaces, overlays, tab indicator, ANSI and syntax decisions; no hex inversion |
| `scripts/build.mjs` | Generate both theme JSONs; retain original glyph geometry/assets |
| `scripts/lib/icons.mjs` | Select only poor-contrast glyphs for brighter variants; native default/Light association handling |
| `themes/obsidian-celluloid-noir-color-theme.json` | Generated 450-color, 43-rule, 30-selector dark theme |
| `icons/obsidian-celluloid-icon-theme.json`, `icons/svg/noir/*.svg` | One shared icon theme with 25 additional same-geometry assets and sparse native Light overrides |
| `presets/obsidian-celluloid-noir.settings.json` | Optional existing typography/layout preset with Noir selected |
| `presets/obsidian-celluloid-auto.settings.json` | Separate optional native macOS/Windows appearance preference snippet |
| `scripts/lib/validation.mjs`, `scripts/validate.mjs` | Shared expected-type, color/syntax/contrast validation and recursive native icon checks; separate reports |
| `scripts/lib/preservation.mjs`, `tests/fixtures/light-v0.2-baseline.json` | Fixed baseline protecting Light artifacts and effective icon behavior |
| `tests/noir.test.mjs`, `tests/tokenization.test.mjs` | Dark-specific regressions and both palettes through real built-in grammars |
| `tests/host.cjs`, `scripts/test-host.mjs` | Native dual-theme loading/switching, schemas, settings and sample modes in a disposable profile |
| `scripts/check-package.mjs`, `scripts/test-install.mjs` | Both contributions, assets/docs/presets, icon readability and the Light baseline checked in the archive and installed extension |
| `package.json`, `package-lock.json` | Version 0.3.0 and additive dark contribution; no new dependencies |
| `README.md`, `CHANGELOG.md`, Noir documents | Both-theme activation, opt-in appearance switching, extraction decisions and validation |

The build validates explicit override IDs against the shared structure. Noir
consumes its own role palette and component treatments, so later dark decisions
do not require changes to Light. The original v0.2 defaults remain in the shared
structure to preserve serialization and behavior. Numbers and built-in primitives
are intentionally amber in Noir and cobalt in Light.

VS Code's [native file icon API](https://code.visualstudio.com/api/extension-guides/file-icon-theme)
uses default associations for dark themes and a `light` override. It does not
provide a `dark` override section. The single shared definition therefore uses
brighter variants by default only where needed and restores original definitions
for Light through that supported mechanism. Every language, extension, filename,
folder and expanded-folder association has the same glyph meaning as v0.2.

## Exact Light preservation

The fixed baseline was captured before implementation. Every build/validation
checks 34 original artifacts by SHA-256: the Light theme JSON, source/reference
palettes, original 56-setting preset, Light design/fidelity documents and all
28 original SVGs. It also compares the original theme/icon contributions,
original icon definitions, tree flags and every effective Light association.

The icon manifest itself necessarily gains dark definitions/default mappings and
Light overrides. Its effective Light output is exact; this is a native compatibility
adaptation, not a change to Light icon appearance or association semantics.
The baseline is never generated by build/test and must not be refreshed to make
a regression pass. Packaging repeats these checks against extracted VSIX bytes.
Older Light implementation/design documents remain available as historical records.

## Validation and reports

Run from the project root with Node 22+ and installed VS Code:

```sh
npm test
npm run test:host
npm run package
npm run test:package
npm run test:install
```

The delivery checks are:

- 47 automated tests passed, no failures/skips; all existing Light cases retained.
- 450 documented workbench IDs, 43 TextMate rules and 30 semantic selectors per theme.
- 55 actual token color assertions per palette across ten language modes, plus
  eight complete representative files per palette, using installed VS Code grammars.
- 269 text pairs per theme: Light minimum 4.68:1; Noir minimum 4.54:1.
- Eight active indicator pairs per theme, all at least 3:1; Noir minimum 4.57:1.
- 140 Noir icon/background checks, at least 3:1; minimum 3.07:1 on reused green glyphs.
- Native host checks for manifest/theme/icon schemas, all three settings preset
  schemas, setting registration, sample language IDs, actual Light → Noir → Light
  activation and retained icon selection. The host waits for asynchronous theme
  loading before asserting the native kind. A multi-theme development host initially
  previews the variant matching its startup scheme; the test explicitly normalizes
  selection in its disposable profile before exercising both themes.
- Official VSCE packaging, extracted archive validation including exact Light
  preservation, and real CLI installation into a temporary profile/extensions directory.

Reports are `dist/contrast-report.json`, `dist/indicator-contrast-report.json`,
`dist/noir-contrast-report.json`, `dist/noir-indicator-contrast-report.json`,
`dist/noir-icon-contrast-report.json`, `dist/host-report.json` and
`dist/install-report.json`. The host report records the actual installed VS Code
version/platform; the install report records the final VSIX SHA-256.

Native validation passed on the locally installed macOS VS Code 1.141.0,
including seven native JSON schema files and all 56 original preset settings. Ventura/Intel,
older supported VS Code versions and other platforms are not independently
certified by these checks. The extension is declarative and performs no runtime
work beyond VS Code loading native theme/icon resources.

## Package, activation and limits

Artifact: `dist/obsidian-celluloid-0.3.0.vsix`. Use **Extensions: Install from
VSIX…**, then **Preferences: Color Theme** to select either variant. Optionally
select **Obsidian Celluloid Icons** through **Preferences: File Icon Theme**.
This delivery does not install into the normal profile or modify global settings.

Automatic OS appearance switching is a separate manual opt-in, documented in
the README and the native appearance preset. The original typography is shared;
global workbench fonts, blur, grain/glow/animations, decorative telemetry/cards,
custom panel geometry and per-tab left frames remain outside the native theme API.
Language semantic providers and terminal applications can affect final colors.
The supplied reference screenshot is not an installed-extension screenshot;
automated tests do not substitute for user visual acceptance on their display.
